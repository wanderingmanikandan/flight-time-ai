The simple idea: distance, speed, and time

Begin with school mathematics

When speed is constant, time = distance ÷ speed. With distance in kilometres and speed in kilometres per hour, multiply by 60 to get minutes.

Time (min) = distance (km) ÷ speed (km/h) × 60

For our assumed speed of 600 km/h, a 1,000 km journey takes 1,000 ÷ 600 × 60 = 100 minutes. This is an invented teaching scenario, not a stated speed for a particular aircraft.

Then learn from examples

In the easy lesson, we use that formula to make the examples. When you press Train, the model fits a straight line to the training pairs. It does not simply return a stored answer for your distance.

A formula would be enough for the easy lesson. We use machine learning here to understand the learning process. With perfect synthetic data, a perfect test score is expected; it does not prove real-aircraft accuracy.

In the real-data lesson, recorded flights do not follow an exact constant-speed line. The model learns an approximate relationship. It does not separately model speed, weather, aircraft type, or phases of flight.

Lesson 1: generated teaching data

20 examples, from 200 to 4,000 km in steps of 200 km. Time = distance ÷ 600 × 60. The fixed speed of 600 km/h is an assumption. These are not measured flight records.

Lesson 2: openly accessible real flight data

The app contains the first 100 data rows of OpenIntro’s nycflights file, which describes a random sample of 32,735 flights departing the New York area in 2013. OpenIntro credits Hadley Wickham’s nycflights13 data; that package identifies the U.S. Bureau of Transportation Statistics as the source.

OpenIntro: dataset description and downloads · Full original CSV · Readable original text data

Original field definitions and BTS attribution

Only two fields are used to fit the model: distance (airport-to-airport distance in statute miles, converted to km using × 1.609344) and air_time (minutes in the air). Recorded airborne time includes airborne phases; the model does not model them separately. No delay minutes or ground time are added. No missing values occur in these two fields in the selected 100 rows.

This is a small historical teaching extract, not an Indian flight dataset or a live worldwide predictor. The first 100 rows were retained without choosing them by model performance. Same routes can appear in both learning and test groups. This is not an evaluation on completely new routes or future years. Recorded targets have not been smoothed or changed.

The examples are embedded in this HTML file. External source links need internet access; training and prediction do not. Source inspected 5 October 2026. Independent teaching app; not an OpenIntro, BTS, or airline product.

For the teacher: method, limits, and publishing on GitHub

What is being learned?

One-feature supervised regression. Ordinary least squares fits time = intercept + slope × distance using training rows only. JavaScript implements the calculation directly; no Python, API, neural network, or external machine-learning library is required.

16/4 train/test rows in the easy lesson; 80/20 in the real lesson. A seeded shuffle (seed 42) chooses the test rows, leaving one minimum- and maximum-distance row in training. This split is deterministic and uses distance, not the answers, to retain the endpoints. The test set never changes when Train is clicked. Switching lessons discards the fitted model and prediction history.

MAE is calculated only on held-out examples. Displayed rules are rounded; predictions use the full-precision fitted coefficients. New predictions are restricted to the training-distance range. The intercept in the real-data line is a fitted number, not an independently measured taxi, take-off, or delay time.

After training, a comparison with a simple no-distance baseline appears here.

Share this app

On GitHub: create a public repository, put index.html at the repository’s top level, and commit the file. In Settings → Pages, select Deploy from a branch → main → /(root) → Save. Use the published link shown there.
